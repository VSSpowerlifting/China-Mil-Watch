What each result means

Every outcome the pipeline can store has a plain-language meaning here. They are translated, not merged: two results that both produce zero records can mean opposite things, and the whole point of keeping seventeen of them apart is that they are seventeen different facts.

What each run result means. An empty return has more than one cause and they are not interchangeable.

unknown_source		 A source was requested that no desk manifest declares. This is a configuration fault, not silence.

storage_failure		 The collected batch could not be committed to storage as a single transaction, so the attempt was rolled back in full. Nothing from it was partially saved, and any previously stored records for this source are unaffected.

Access refusals are respected, not worked around

When a source refuses an honestly identified collector — a login wall, a redirect off its own domains, or a challenge page served in place of a listing — the refusal is recorded as the outcome and collection stops there. No browser impersonation, no challenge solving, no proxying. An institution that wants to refuse this collector must be able to recognise it and say so, and defeating a refusal would destroy the capability that rule protects.

Why this table is on the site rather than in a changelog

A corpus with undisclosed holes cannot be cited safely. Anyone using this archive to argue that an institution went quiet during one of these windows would be wrong, and would have no way of knowing.
