# Korea originals — restricted custody decision and evidence-preserving cutover plan

**Proposal only — October 15, 2026.** This document does **not** authorize a storage move, erase already-public objects, change GitHub access, enable the DAPA issuer, admit Korea to production, submit any material to AI, or enable Sunday email. Parent owner decision: [#520](https://github.com/VSSpowerlifting/China-Mil-Watch/issues/520). Editorial and source gates: [#221](https://github.com/VSSpowerlifting/China-Mil-Watch/issues/221), [#601](https://github.com/VSSpowerlifting/China-Mil-Watch/issues/601).

## 1. What the repository actually does today

The repository `VSSpowerlifting/China-Mil-Watch` is **public**. Its orphan branch `shadow/korea-policy-briefing` is a public Git ref, **not** private storage. The shared [Indonesia/Korea shadow workflow](../../.github/workflows/indonesia_korea_shadow.yml) runs Korea at nominal **17:47 UTC** and Indonesia at **17:17 UTC**. It clones the desk's orphan branch into `$RUNNER_TEMP/candidate-state`, executes `scripts/shadow_collect_desk.py` with `--lookback-days 6 --cap 40`, and uses a job-level `contents: write` token to commit **all of `state/`** to that ref. Its schedule and existing branch need separate migration consideration; changing Korea must not affect Indonesia.

The frozen Korea review reference, **`0595f0fd29b769cbab5dd57c2ef57af174237a67`**, has **14** distinct portal article `newsId` / downloaded HWPX `fileId` pairs, not the five counted when #520 was first opened. The [14-original register](../../research/korea/MND_HWPX_14_ORIGINAL_SOURCE_REVIEW_REGISTER_2026-10-14.md) records HWPX response hashes and source identities without exposing original text. There were **nine ledgers on eight target dates** (Oct 6–11, 13–14); **the scheduled October 12 attempt failed**. Subsequent lookbacks do not turn October 12 into a successful scheduled collection. HWPX extraction parity can pass while chronological continuity still fails.

The current workflow's Korea-specific Actions upload includes only `state/ledger/*.json`, `state/clock.json` and `candidate-run.log` (90-day retention). This reduces future *artifact* exposure, but it does **not** hide full body text, `state/shadow.db`, HWPX, HTML, or other capture bytes in the public **Git branch**. Older `candidate-state/state/` Actions artifacts may still contain original files; inventory their surviving copies separately. Git history, clones and caches may persist after a future cleanup.

The captured MND-republished portal pages carry page-level **KOGL Type 1, attributed text-only** markings for the 14 currently audited sources ([#607](https://github.com/VSSpowerlifting/China-Mil-Watch/pull/607)). Neither those markings nor a user's review of Korean text clears complete HWPX containers, third-party imagery, media, confidential research, external AI processing, bulk replication or public release. [#602](https://github.com/VSSpowerlifting/China-Mil-Watch/pull/602) proposes publicly stored **short authored synopses** under a "private" (meaning no-Sunday/no-send) workflow; those repository files are not confidential.

## 2. Recommended decision — separate private custody from public receipts

**Preferred target:** a **new private Git repository** dedicated to Korea original-evidence custody, with a restrictive collaborator list and dedicated collector credentials. Git is the lowest-friction format for the existing orphan-branch clocks, ledgers, immutable commits and source hashes. A private object store with versioning and an append-only manifest is a valid alternative, but requires more adapter/locking/audit engineering. *A new branch in this public repo, GitHub Actions artifacts, or a password-protected local HTML page are not privacy controls.*

| Data class | Proposed future location | Public Git allowed? |
|---|---|---|
| Complete HWPX/PDF/media, original Korean bodies, archived HTML, `shadow.db`, original reviewer notes | Restricted private evidence store | **No** |
| Exact source IDs, issuer, URL, SHA-256 digests, collector commit, immutable state commit, logical-slot outcome, rights gate and review status | Carefully reviewed, minimal public metadata receipt | **Only as necessary, not originals** |
| Short original authored synopses | Public Git only if editor/owner explicitly accepts public visibility; otherwise private editorial store | **Not automatically confidential** |
| Signed Korean-language review and license/attribution adjudication | Restricted evidence store with reviewer identity, timestamp and pinned source version | **No personal reviewer details in public artifacts** |
| Approved public IPR records | Existing governed publication system, only after separate source/rights/owner gates | **No automatic promotion** |

The private repo name, ownership, access list, token provisioning, retention policy, and data-processing limitations are **not chosen yet**. Do not create or move credentials in a public PR. A workflow's `GITHUB_TOKEN` scoped to one repository should **not** be assumed to write to another private repository; prefer a narrowly scoped GitHub App installation token or fine-grained repository-scoped credential, provisioned only through approved protected secrets and reviewed workflow permissions. Avoid printing remote URLs containing tokens, body text, capture bytes or sensitive review records.

## 3. Gate-by-gate cutover: no deletion and no reset of history

1. **Owner choice (hold):** explicitly approve the restricted destination, custodians, retention, backup/recovery, allowed reviewer access and whether existing public archive copies may be removed *after* verification. Obtain any necessary copyright/terms assessment separately; moving data does not grant rights to keep it.
2. **Freeze/inventory (read only):** record exact public Korea shadow ref tip, full Git tree/object inventory, source IDs and all existing capture SHA-256 values, actual latest ledger and clock, 7/14/30-day qualification records, repository Actions artifacts with run IDs/names/retention, and known historical copies. Generate only hashes/counts/pointers in any public receipt. Label the Oct 12 scheduled miss as `FAIL`; distinguish cron attempt from lookback coverage. Do not mistake this October 15 proposal's frozen 14-original snapshot for the moving current tip.
3. **Provision private storage and tested backup (explicitly approved operation):** configure repository visibility, minimal readers/writers, protected credentials, encrypted recovery/backups and immutable evidence conventions; validate a restore to a *separate* non-public test location before cutover. Do not place files in a temporary public fork, public CI artifact or public release.
4. **Copy and independently verify (no live writer change yet):** migrate the complete original Git history and evidence to the private target without modifying original capture bytes. Verify *every* input-vs-destination capture SHA-256, shadow database integrity, clock, each ledger/date, original Git commit ancestry/metadata and per-record identity. Preserve the frozen 14-original review commit and older five-original reference snapshots. A migration copy has no authority to repair the Oct 12 failure or mark review complete.
5. **Single-writer cutover (separate engineering PR):** coordinate a planned pause/hold of **Korea only** so public and private schedulers never concurrently write. Split or parameterize the current combined workflow without changing Indonesia's behavior. Under owner-reviewed credentials, point the Korea-only writer at private custody; remove Korea write privileges to the old public ref; preserve the original logical day-zero, cron and ledgers without silently restarting the qualification clock. Fail **closed** when private credentials or verified private state are missing; no fallback to the old public branch or public artifacts.
6. **Post-cutover replay:** perform read-only source/hash audits against the private target; verify at least one genuinely scheduled new logical slot, exact-source identities, provenance and false admission flags. Confirm Indonesia's original workflow behavior is unchanged. Observe successful *and failed* runs, artifact contents, log redaction, checkout token scope and lack of original-source output to public systems. Do not claim a completed 7-day window from a one-off success.
7. **Historical public exposure disposition (separate explicit decision):** identify public refs, Git objects and historical Action artifact URLs that remain accessible. Only after a verified backup and owner-approved preservation/rights plan consider artifact deletion, public-ref retirement or history-cleaning. Public history rewriting cannot retract prior clones or establish retroactive confidentiality. Never force-push/delete as a side effect of migration PR merge.

## 4. Acceptance conditions for engineering PR and the owner

- A migration implementation PR must contain focused **offline** failure-path tests for missing private credential/ref, mismatched hash, stale state, concurrent writer, unexpected artifact content, wrong issuer, protected historical gap and Indonesia preservation, plus exact-head full CI.
- Exactly one authorized Korea writer is active; **no scheduled Korean originals are committed to a public Git ref or uploaded as artifacts** after cutover. Verify actual logs and job permissions, not just workflow comments.
- For every preserved article/HWPX/page-capture pair and ledger, input and destination cryptographic hashes match; provenance crosswalk lists old and new Git commits, the original logical clock and the October 12 failed attempt.
- Private restore has actually succeeded; reviewer documents/signoffs are access-controlled. Public outputs contain only vetted metadata and never HWPX, HTML, full source prose or personal reviewer notes.
- Existing production `pla_watch.db`, `output/`, public sources, Korea site, Sunday writer/email, AI access, DAPA collection and publication approvals remain untouched. Rights, semantic review and separate release authorization remain independent holds.
- Failed verification means **stop without switching writer or deleting public evidence**; write a metadata-only failure receipt and obtain new owner direction.

## 5. Explicit requests before implementation

The owner needs to choose **private Git repository vs private object storage**, designate people with archive access, decide backup/retention expectations, and authorize a *separate* credential/cutover implementation. This proposal recommends **private Git** as the simplest evidence-preserving architecture; that is **not permission to create a repo, transfer original files, disable the Korea collector, or change the public archive**.

**Disposition:** `PROPOSED / NO CUTOVER AUTHORIZED`. #520 stays open; #221 source-use controls stay closed.
