## Operator-only authenticated, metadata-only census

Run in an **already authenticated** owner-controlled shell with the GitHub CLI installed. Output is intended for restricted local review and is not automatically published or uploaded. Do not paste CLI tokens, publisher bodies or private ZIPs into PRs or comments.

```sh
# Run multiple <=35-day windows starting August 1; keep each output unique.
# Example at a later owner-audited run: replace timestamp with actual UTC now
python3 scripts/inventory_ipr_actions_artifact_expiry.py \
  --from-date 2026-10-07 \
  --through-date 2026-10-15 \
  --as-of-utc YYYY-MM-DDTHH:MM:SSZ \
  --out /restricted/evidence-inventory/collector-actions-20261015.json
```

`--as-of-utc` must be a **real UTC timestamp at or before the operator's collection time**. The implementation fixes repo scope to `VSSpowerlifting/China-Mil-Watch` and requires 1–35 contiguous calendar days from August 1 onward, not a selector the caller can use to query another account or endpoint. It invokes `gh api --method GET` for each day's `schedule`/`workflow_dispatch` collection runs (under each day’s **complete repo Actions run listing**, not fragile top-5 workflow search) and checks stable GitHub `total_count`, every pagination page, unique run IDs and `created_at` date. It then paginates every retained in-scope run's artifacts, validates scope and expiry, and records names/IDs/byte counts/attempt labels. The census now also retains GitHub's provider-side **upload-time SHA-256 digest** as `provider_sha256` (hex only), when supplied in the API's `digest: sha256:<hex>` field. A missing digest is explicitly `null` with a `provider_artifact_digest_unavailable` hold; a malformed non-null digest aborts the census instead of inventing a checksum. The count and provider digest are metadata, never a locally verified downloaded ZIP. Each artifact’s `name_attempt` is inferred **only** if its filename ends in the proven `-<run_id>-<attempt>` pattern; ledger-only/no-suffix names remain ambiguous.

**Retained-run coverage** includes active Indonesia/Korea shared workflow, AFP and NSC, Vietnam ministry and legacy Vietnam shadow, Singapore MINDEF, Japan MOD, Japan JCG guarded and JCG manual, and the legacy U.S. Indo-Pacific collector. An event/path outside this declared list is ignored; review workflow name additions before claiming family exhaustivity. Multiple jobs in a shared Indonesia/Korea run do not automatically establish which original-source family was selected; desk-specific audits must reconcile source identity. **Rerun attempt validation:** when GitHub reports `run_attempt > 1`, the operator tool now additionally queries `actions/runs/<run_id>/attempts/<attempt_number>/jobs` **for each attempt number**, with stable bounded pagination and scope checks on every job's `run_id` and `run_attempt`. It preserves the actual original `job_id`, status, and conclusion in an explicit `historical_attempt_jobs` receipt. A prior **failed**, cancelled or unfinished job remains an explicit `historical_failed_or_unfinished_job` hold even if the latest top-level run is successful; an attempt with no retained job row is an `attempt_has_no_retained_job_evidence` hold. This is a real **Jobs API receipt**, not a raw ZIP provenance or source-fidelity proof. Missing individual attempt-labeled artifacts generate a separate hold even if job history is complete; later job success never retroactively repairs failed source collection.

**Explicit output limits:** only the *retained* repository API catalog at audit time, not deleted runs, expired artifact contents, actual source-original bytes, rights, or backup. An authenticated API response that supplies `provider_sha256` makes it possible for a **separate owner-authorized ZIP download verifier** to compare its exact opaque ZIP SHA-256 to the provider's upload-time digest. It does not prove a download took place, establish the HTTP redirect/session chain on its own, authenticate the ministry-produced bytes *inside* the artifact, supply a signed independent GitHub attestation, or grant copyright/source retention rights. An artifact reported `expired=false` may still later vanish; capture the live provider metadata receipt and preserve its exact evidence before expiry under source-specific lawful retention. A zero-result day is not a green desk-qualification result; compare to the governing schedule and source-specific expected ledger dates separately. Retention report `production_cutover_authorized=false` is unconditional.

The worktree-output guard prevents overwriting an existing evidence-inventory JSON. No artifact-download endpoint, GitHub App writer, API secret in PR contexts, scheduled monitoring, source-state mutation, shadow-state promotion, permission flag, website deploy or private-vault data write is present.
