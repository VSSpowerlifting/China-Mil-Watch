# IPR private vault — encrypted Actions ZIP evidence sidecars

**15 October 2026. Owner-controlled offline recovery tool, NOT a live collector change.**

**Current custody update (October 15):** Nine genuine source Git histories have been transferred and read back from the private vault. This is separate from the **still-incomplete ZIP-only failed-attempt evidence preservation**; no independently encrypted off-GitHub backup or recovery is claimed. Under the owner's GitHub-only decision, this GPG tooling is optional rather than a mandatory migration gate. [PR #617](https://github.com/VSSpowerlifting/China-Mil-Watch/pull/617) covers referenced native Git history. That alone cannot preserve the **only remaining original bytes from a failed collection attempt**, which can exist in a GitHub Actions ZIP even if the source branch never pushed.

This complementary preparation builds one GPG-encrypted ZIP *sidecar* from the operator's existing, authenticated local Actions artifact downloads. **Merged dependency:** [PR #638](https://github.com/VSSpowerlifting/China-Mil-Watch/pull/638) added GitHub's upload-time `provider_sha256` to the #620 census; the ZIP backup now requires each staged ZIP's SHA-256 and file size to match that provider metadata before encrypting. A pre-#638 census without provider hashes now **HOLDs**; recapture the metadata in an authenticated owner session. Both [#624](https://github.com/VSSpowerlifting/China-Mil-Watch/pull/624) and #638 are merged; the remaining requirement is authenticated, complete preservation and recoverable readback of actual ZIP-only evidence. The ZIPs are kept **opaque**: no government source text, images, HTML, filenames inside ZIPs, or permissions are extracted, interpreted, printed or uploaded. It preserves ZIP SHA-256 and compressed byte lengths, artifact IDs and run/attempt labels **as asserted by the supplied inventory**, and the [#620](https://github.com/VSSpowerlifting/China-Mil-Watch/pull/620) operator census file SHA-256. The *entire* sidecar manifest is encrypted alongside the bytes. No publisher or GitHub network calls, repo push, source-state mutation, model or email occurs.

## Two separate tools and custody requirements

1. **Discover retained runs and artifacts** with `scripts/inventory_ipr_actions_artifact_expiry.py` from merged #620, using a restricted authenticated owner shell. Keep the original JSON receipt immutable and separately backed up. Query all relevant days and inspect **every historical attempt's job**; a successful top-level rerun must not conceal a prior failed attempt.
2. **Download actual artifact ZIPs** through an owner-authenticated GitHub workflow outside public PR CI, after source-original retention permission and destination controls are decided. This PR **does not provide a downloading tool**, and no actual ZIPs were fetched or uploaded in its CI. Keep one file per original GitHub artifact, named exactly `artifact-<numeric_artifact_id>.zip`, in a private local directory. Verify IDs via the GitHub Actions API in the same authorized session. The backup script now additionally compares every staged ZIP's exact bytes and uploaded ZIP SHA-256 against the authenticated census's GitHub provider metadata. **This is provider-upload-byte parity, not independent authentication of the download HTTP redirect/session** or of publisher documents inside the artifact. Keep receipts for ZIP fetch date/source, identity, HTTP status, and source rights. Do not trust downloaded files with names that claim official provenance without validating that chain.
3. **Encrypt all artifacts for exactly one run** with `scripts/private_vault_encrypt_actions_attempts.py`; no partial selection. **Stage downloaded source ZIPs and ciphertext outside every Git worktree or bare repository.** The script now refuses either directory if it is within a Git repository to reduce accidental public commits. The program refuses absent or extra staged files, wrong/unknown artifact IDs, missing GitHub provider digests, wrong staged ZIP SHA-256 or ZIP size, unavailable/expired metadata, absent or malformed past-rerun jobs, duplicate historical job IDs, inconsistent job failure flags, missing artifacts for any reported attempt, modified files during export, a mismatch in the exact ZIP bytes streamed to GPG, wrong decryption key, and existing output targets. The supplied GPG public encryption-key fingerprint must already be trusted locally. Its encrypted final file is created without overwriting any existing target, then the containing directory is fsynced before the program reports success; a failed filesystem durability check remains a HOLD, not an automatic backup certification. The *private* decryption key stays offline, outside GitHub Actions, GitHub Issues and ChatGPT.
4. **Verify the ciphertext from an independent backup medium**, separately retain the exact input JSON receipt and its SHA-256, and run the sidecar restore/check in a private owner-controlled scratch directory. It **streams decryption directly into a bounded TAR reader without writing a plaintext TAR or extracting ZIPs onto disk**, validates strict unique member names, member/total byte limits and checksums, **enforces the declared attempt count, per-attempt coverage and manifest item count on recovery**, and refuses a world-readable scratch directory. **Restore now requires the separately retained original census JSON** as well as its independently recorded SHA-256; it compares workflow/event, exact attempt count and every artifact ID, size, attempt label and provider digest against that original receipt. A coherent forged manifest cannot silently rewrite the recorded run history. Even a fictional re-encrypted ZIP whose altered manifest coherently omits the failed attempt is refused; this is structural consistency, **not** independent GitHub download authentication or signed origin provenance. Both the compressed original ZIPs and all publisher-contained files remain opaque. The decryption subprocess is killed on failure and no plaintext backup artifact is retained. A green restore verifies ZIP-byte preservation, records parity with the supplied original census, and preserves the provider SHA-256 recorded at creation; it does **not** verify any original inside those ZIPs, source-retention permission, the authenticated download HTTP chain or producer provenance. Both creation and restore receipts **always** report `downloaded_zip_origin_authenticated=false`: that requires separate trustworthy GitHub download provenance evidence, not an ID embedded in a local filename.
5. **Explicit separate custody gates** remain for all Git branch histories and source extraction, all source-specific media/copying permissions, Git LFS bytes, every missed/failed manual/scheduled attempt, independent encrypted backup location, and the owner-approved live collector cutover. Do not merge [draft AFP #606](https://github.com/VSSpowerlifting/China-Mil-Watch/pull/606) simply because an encrypted sidecar tool passes synthetic tests.
