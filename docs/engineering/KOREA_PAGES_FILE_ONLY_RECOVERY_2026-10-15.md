Actual failure evidence:
- First guarded run attempt stopped after an unrelated repository merge advanced `main` during the render.
- A safe rerun checked out current `main`, passed its complete Korea source-link rendering/validation and tracked database SHA checks, but found five rendered changes: `output/korea.html` plus unrelated `archive.html`, `browse.js`, `corpus-index.json` and `index.html` generated by other archive work. Existing safeguard **correctly forbids** uploading `./output`, which would have carried those unrelated changes.

## Scope-correct delivery mechanism

`.github/workflows/korea_pages_file_only_release.yml` is a separate one-time push-triggered + explicitly rerunnable `workflow_dispatch` job. It keeps the established `daily-update` GitHub concurrency group. It checks out current main and pins its exact Git SHA plus production DB checksum; renders and validates the actual website; rechecks 5+9 IDs and source URLs, disputed excavation-year notice, copyright/metadata boundaries and Korea's public/shadow status; validates the site and DB.

The renderer **may regenerate other files, but this workflow can transfer only `output/korea.html`**. It stages and commits exactly that file on main, checks the main SHA has not changed before an ordinary fast-forward push, and never stages any other generated files. No full-tree Pages upload follows.

It then independently checks out the *existing* `gh-pages` branch without resetting, force-pushing or removing anything. Only `korea.html` is overwritten by the verified rendered HTML and staged. The workflow checks exact file equality, forbids other staged files, tests the gh-pages SHA for concurrent changes and uses an ordinary fast-forward push. Every other Pages file, image, stylesheet and CNAME stays exactly as it was.

If another branch moves, the job fails safely. Its manual retry checks out **fresh current main** and repeats the entire source/page/DB validation. GitHub Actions logs and a successful merge are not proof of public delivery; final verification requires `main:output/korea.html` and `gh-pages:korea.html` both show exactly five original plus nine additional links, and all other `gh-pages` files remain unchanged by the file-only commit.

This intentionally does not weaken the old full-tree guard, alter other desks' output, rehost Korean originals, change rights/AI/editor admissions, or promote Korea to production. It simply delivers the specifically owner-approved public link-only HTML without dragging other website changes into the deployment.

Merge only with current-head full and focused CI success and scoped file audit. Publication triggers on merging the new workflow file and must be observed independently on GitHub Actions and the deployed Pages branch.
