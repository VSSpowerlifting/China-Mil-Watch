# Korea verified metadata → isolated SQLite import rehearsal

**October 15, 2026 — operational production prep.** The next stage after #656 (live-compatible normalized collector evidence) and #658 (source-version-bound, independently signed reviewer and owner scope checks) is a disposable metadata-only database rehearsal. This tool is stacked on those two PRs and must not be merged, deployed, or called production without them.

## Exact input trust chain

The caller supplies a secured, already available Korea shadow Git checkout; the versioned candidate packet generated by #656; complete independently created reviewer and owner HMAC seals for source versions selected for review; **two separately provisioned trusted 32+ byte keys**; a truthful UTC evaluation instant; and a **new file** under an owner-only 0700 parent outside both the public IPR checkout and the source checkout.

The tool *rebuilds* the candidate packet by invoking #656's full source reread (immutable source Git ancestry, captured HWPX bytes and re-extraction, publisher HTML/text hash parity, ledger and Day 0). It compares the complete canonical packet exactly against the supplied one. This prevents changing source bodies, issuer, commit, or metadata between review and rehearsal without a new signoff.

Each supplied review seal then independently passes #658's strict schema, separate reviewer and owner HMAC, signed exact source version, rights, approval-order and chronology-exception gates. If even one supplied seal is invalid, the entire rehearsal stops **without creating a SQLite file**. One source may have only one signed review. Explicit signed **hold** reviews remain uninserted; records without signed reviews remain uninserted.

## Actual staged record schema

Only records with verified `reviewed_official_link_metadata_only` scope are copied into a transient SQLite table containing:

- source identity, immutable state/source version SHA and original shadow database SHA;
- SHA-256 fingerprint of the complete, independently signed reviewer+owner seal (the seal itself remains in restricted custody);
- canonical government outbound URL and portal date;
- source publisher and original issuing institution stored separately;
- syndicated/authority classification;
- SHA-256 pins for the original title, complete text, captured official portal page and HWPX;
- fixed `metadata_only_rehearsal_not_production` status.

An individual rehearsal row cannot independently authenticate review or rights: the new `signed_review_sha256` is a lookup/integrity anchor, not permission. A future production importer must retrieve the privately held exact sealed decision, verify both HMACs and full source evidence again, and reject a missing or mismatched receipt. The SQLite file is never sufficient authority on its own.

**No original title, Korean article body, embedded images, translation, English summary, model text, signing key, reviewer identity, database article ID, corpus approval status, production write, site record or Sunday email is permitted.**

All writes first happen in SQLite `:memory:` with deterministic sorted rows and explicit duplicate/idempotent replay tests. Only after full local validation is the scratch SQLite database created atomically as owner-only 0600 output at the chosen path. Errors refuse and remove any partially created scratch file.

The CLI/publishing integration is deliberately absent: the API requires trusted private caller state and signer keys and does not read GitHub repository secrets or post release artifacts to CI. The focused CI uses **synthetic fake source packets and fake keys**, with an explicitly patched source-checkout validator for isolated logic tests; it does not prove real Korea collection or source-rights approval. No real source run occurred in this PR.

## Deployment and release blockers

This is a meaningful **disposable database rehearsal**, not a claim that Korea is live. Real production admission still needs authentic source-specific reviews and trusted signer provisioning, legally scoped attribution and permitted use, an independent private original archive with successful restore, a qualified scheduled collection window, a source-specific production schema/importer able to represent Korean source provenance, and a guarded website/article release with rollback. User-approved government link-only publication of 14 sources does not grant blanket rights to future records.

**Next coding target:** map this rehearsed, source-versioned metadata schema to a reviewed country-neutral IPR production database migration and an owner-gated production importer. Explicitly retain three independent authorities: source collection, editorial/source-use admission, and public website publishing. Site changes remain outside this PR.
